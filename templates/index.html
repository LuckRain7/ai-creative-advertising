写作模板 ​

这个知识库的价值不在第一版写了多少，而在于每做完一件事都往回填。

填的时候不要从空白页开始——空白页会让人拖延，也会让每篇的结构都不一样，久了就没法横向对比。用模板。

三个模板 ​

模板什么时候用存到哪
Prompt 卡片模板调通了一条 Promptdocs/prompts/
案例拆解模板做完一个项目docs/cases/
工具评测模板试完一个新工具docs/tools/

加一篇新文章的完整步骤 ​

  1. 复制对应模板的骨架，在目标目录新建 .md 文件（文件名用英文小写连字符，如 perfume-key-visual.md）
  2. 打开 docs/.vitepress/config.mts，在 sidebar 对应板块的 items 里加一行
  3. npm run docs:dev 本地看一眼
  4. git commit + git push，1–2 分钟后线上生效

第 2 步不能省

不在 config.mts 里加链接，文章不会出现在侧边栏——虽然搜索还能搜到，但基本等于没写。

什么值得写 ​

一个筛选标准：下次遇到同类需求，这条记录能帮你省多少时间？

值得写：

  • 试了五版才调对的 Prompt，以及前四版为什么不行
  • 某个效果做不出来，最后靠换链路绕过去的
  • 客户反复否掉的方向（避坑同样是资产）
  • 某个工具在你的具体场景里的实际出片率

不值得写：

  • 官网文档上抄来的参数（会过时，随时能查）
  • 只用一次的一次性内容
  • 没有结论的流水账

一条写作原则 ​

失败的记录比成功的更值钱

"这个方法有效"只在当时的条件下成立，条件一变就未必。 "这个方法无效，因为 X" 标记的是边界，边界比路径稳定得多。

所以三个模板里都留了「失败的尝试」「翻车点」「如果重做一次」这类段落。不要跳过它们。
