# 怎么用这个知识库

## 日常怎么查

站点右上角有搜索框（也可以按 `/` 唤起），全文检索，纯本地运行。

查东西的时候，按「你想要什么」而不是「用什么工具」去搜更容易命中：搜「产品图 反光」比搜「Midjourney」有用，因为前者是问题，后者是零件。

## 怎么往里加内容

这个库的价值不在于第一版写了多少，而在于**每次做完一个项目都往回填**。填的时候不要从空白页开始，用模板：

| 你想记录的东西 | 用哪个模板 | 存到哪 |
|---|---|---|
| 一条调通的 Prompt | [Prompt 卡片模板](/templates/prompt-card) | `docs/prompts/` |
| 一个做完的项目复盘 | [案例拆解模板](/templates/case-study) | `docs/cases/` |
| 一个新工具的试用结论 | [工具评测模板](/templates/tool-review) | `docs/tools/` |

### 加一篇新文章的完整步骤

1. 复制对应模板的内容，在目标目录下新建 `.md` 文件（文件名用英文小写连字符，如 `perfume-key-visual.md`）。
2. 打开 `docs/.vitepress/config.mts`，在 `sidebar` 对应板块的 `items` 里加一行链接。**不加这一步，文章不会出现在侧边栏。**
3. 本地 `npm run docs:dev` 看一眼。
4. `git commit` 并 `git push`，GitHub Actions 会自动构建发布，一般 1–2 分钟生效。

### 什么值得记

一个筛选标准：**下次遇到同类需求，这条记录能帮你省多少时间？**

值得记的：

- 试了五版才调对的 Prompt，以及前四版为什么不行
- 某个效果做不出来，最后是靠换工具/换链路绕过去的
- 客户反复否掉的方向（避坑同样是资产）

不值得记：

- 官网文档上抄来的参数列表（会过时，且随时能查）
- 只用一次的一次性 Prompt

## 本地开发命令

```bash
npm install          # 首次克隆后执行一次

npm run docs:dev     # 本地预览，改 Markdown 自动热更新
npm run docs:build   # 构建静态站点，顺便检查死链
npm run docs:preview # 预览构建产物（和线上一致）
```

::: warning 构建失败最常见的原因是死链
配置里开了 `ignoreDeadLinks: false`，任何指向不存在页面的内部链接都会让构建直接报错。这是有意的——宁可本地失败，也不要线上 404。报错信息会指出是哪个文件的哪一行。
:::
