# 案例拆解

案例的价值不在于"看别人做得多好"，而在于**看清楚一条创意是怎么一步步变成成片的**，然后把其中可复用的部分抽出来。

| 案例 | 核心技术点 | 核心判断 |
|---|---|---|
| 01 · 饮料 TVC | 图生视频优于文生视频 | 把情绪变化编码进色彩 |
| 02 · 电商主图 | 批量生产的一致性控制 | 先做完美 1 张，再复制 N 次 |
| 03 · 薯条短视频 | 首尾帧控制形变动作 | 不是所有广告都需要 Big Idea |
| 04 · VF 薯条脆 | 生成实拍不到的画面 | 展示做法，不展示好处 |

::: tip 03 和 04 建议对照着读
同样是薯条，一个卖**感官**（热和脆），一个卖**工艺**（VF 真空低温油炸）。

卖点性质不同，整条链路都不同：03 不需要 Big Idea、不需要法务审校，把感官做足即可；04 有一整天花在技术核查与合规审校上，不产出任何画面。

**这两篇放在一起，比任何一篇单独看都有价值。**
:::

::: warning 关于这四个案例
它们是**教学用的演示案例**，用来展示拆解格式怎么用、一条链路的各环节怎么衔接。它们不是真实客户项目的复盘。

真正有价值的是你自己项目的记录。做完一个项目就用 [案例拆解模板](/templates/case-study) 写一篇——那些才是别人抄不走的东西。
:::

## 怎么读案例

不要顺着读一遍就完了。带着三个问题读：

1. **它的 Big Idea 是什么？** 用一句话复述。复述不出来，说明这个案例的创意本身就不清晰。
2. **哪一步是决定性的？** 一条链路里通常有一两步决定了成败，其余是执行。找出那一步。
3. **哪部分能直接搬到我的项目？** 通常不是创意（创意不能抄），而是**流程和参数**。

## 怎么写案例

做完项目就写，别拖。三天后就想不起来当时为什么做那个决定了。

写的时候重点记两类东西：

- **失败的尝试**。比成功的做法更有价值——它标记了边界在哪。
- **决策的理由**。「为什么选 A 不选 B」，这是下次能复用的判断，具体参数反而会过时。

用 [案例拆解模板](/templates/case-study)。
