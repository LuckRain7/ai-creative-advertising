# 作战区

::: danger 这个板块完全公开，且没有任何技术兜底
这里放**真实客户项目的进行中记录**。它和站点其他板块一样会发布到线上，也会留在 GitHub 提交历史里——**删得掉页面，删不掉历史**。

曾经存在过「dev 可见 / build 排除 / git 排除」的三层隔离，**已于 2026-08-06 全部移除**（经过见 `specs/2026-08-05-lab-module-design.md`）。这意味着：**提交即公开，推送即上线，写进去就撤不回。**

所以下面这张表是唯一的控制点，写之前过一遍：

| 不写 | 原因 |
|---|---|
| 客户明确要求保密的信息 | 保密义务 |
| 未公开的价格条款、合同细节 | 商业敏感 |
| 第三方提供的未授权素材 | 版权 |
| 对客户沟通行为的负面评价 | 客户会看到 |
| **拿不准的** | **拿不准本身就是不写的理由** |
:::

## 和其他板块的区别

| 板块 | 回答什么 | 什么时候写 |
|---|---|---|
| [方法论](/method/) [Prompt 库](/prompts/) [工具地图](/tools/) | 该怎么做 | 事后提炼 |
| [实战流水线](/pipelines/) | 这套工具组合怎么跑 | 事后提炼 |
| [案例拆解](/cases/) | 别人 / 演示项目怎么做的 | 事后复盘 |
| **作战区** | **这个项目做到哪了、下一步做什么** | **进行中，边做边写** |

**这里的文件是工作产物本身，不是记录。** `01-proposal.md` 就是要发给客户的那份提案，写完直接用，不是「提案的总结」。

## 项目看板

| 项目 | 阶段 | 卡在哪 |
|---|---|---|
| [双宇食品 · 薯条脆](/lab/shuangyu-fries/) | 2 · 对客（客户已回第一轮） | **全是物料**——包装源文件（需终稿）、配料表 / 营养成分表、实物打样件、预计上市时间 |

## 阶段与放行条件

| 阶段 | 产出 | 放行条件 |
|---|---|---|
| 0 · 立项 | `00-brief` | 已知与未知划分清楚，风险列出 |
| 1 · 提案 | `01-proposal` `02-materials` | 内部讨论通过 |
| 2 · 对客 | 反馈写回 `00-brief` | 方向确认、物料到位 |
| 3 · 分镜 | `03-storyboard` | 逐镜标注可生成性 |
| 4 · Prompt | `04-prompts` | 按工具分组，不可生成的标出替代方案 |
| 5 · 生成 | `05-genlog` | 全片跑通一版再抠单镜 |
| 6 · 后期交付 | 成片 | —— |
| 7 · 复盘 | `06-review` | 交付后立刻写 |

::: warning 阶段 1 没放行，不要写分镜和 Prompt
提案方向一变，分镜全废。这是这类项目里最容易发生的浪费。
:::

::: tip 最容易被跳过、也最值钱的一份是 `05-genlog`
真实出片率只能当场记，事后一定记不准。[案例 06](/cases/case-06-kalshi-veo) 之所以是整个知识库信息量最大的一篇，就是因为原作者当场记了废片数。
:::
