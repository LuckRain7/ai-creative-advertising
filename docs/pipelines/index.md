# 实战流水线

方法论讲**该怎么做**，Prompt 库讲**那一句怎么写**，工具地图讲**用什么**。这个板块讲的是把它们串起来之后，**一条具体的链路实际怎么跑**。

## 和其他板块的区别

| 板块 | 回答 | 是否绑定具体工具 |
|---|---|---|
| [创意方法论](/method/) | 该怎么推进 | 否，工具无关 |
| [工具地图](/tools/) | 用哪个工具 | 是，但只讲定位 |
| **实战流水线** | **这套工具组合起来怎么跑** | **是，绑得很死** |

::: warning 这个板块的内容保质期最短
流水线绑定具体工具的具体形态。工具改版，整篇可能就得重写。

**这是有意的取舍**——换来的是可操作性。方法论页面写得再稳，也回答不了"我下载的文件该怎么归档"。
:::

## 什么样的内容适合写成流水线

三个特征，缺一个就不必单开一篇：

1. **跨工具**。单个工具的用法归 [Prompt 库](/prompts/) 或 [工具评测](/tools/reviews)。
2. **有交接问题**。两个系统之间靠人搬运，就一定有命名、归档、版本的规矩要定。
3. **重复跑得起来**。只做一次的链路不值得沉淀——**建流水线本身是有成本的，要在第二个项目才回本。**

## 写自己的流水线

暂时没有专用模板，[案例拆解模板](/templates/case-study) 的结构基本够用。重点记三件事：

- **交接界面长什么样**（目录结构、命名规范）——这是流水线的命脉
- **哪一步没能自动化，为什么**——比能自动化的部分更有价值
- **搭建成本**（第一次花了多久）——决定别人要不要跟
