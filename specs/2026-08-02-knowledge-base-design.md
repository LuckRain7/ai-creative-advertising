# AI 创意广告知识库 — 设计文档

日期：2026-08-02

## 目标

搭建一个既服务于个人实战沉淀、又可公开阅读的知识库站点，主题为「借助 AI 生成创意广告」。产物必须能直接部署到 GitHub Pages。

## 定位

双重身份：

- **对内**：自己的作战手册。Prompt 可直接复制，方法论可直接照做，案例可直接抄套路。
- **对外**：可读的教程站。陌生人从首页进来，能沿着「入门 → 方法论 → Prompt → 工具 → 案例」走通一条路径。

写作原则：**能抄走的比能读懂的更重要**。每篇文章都要落到可执行的动作上。

## 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 站点框架 | VitePress 1.6.4 | 纯 Markdown 写作，自带侧边栏、本地搜索、深浅色、响应式。构建快，配置面小。 |
| 搜索 | VitePress 内置 minisearch | 纯静态、零外部服务、零费用。 |
| 部署 | GitHub Actions → GitHub Pages | push 到 `main` 自动构建发布，无需手动维护 `gh-pages` 分支。 |
| 界面语言 | 中文（zh-CN locale） | 全站中文，含「上一页/下一页」「最后更新于」等 UI 文案。 |

不选 Docusaurus：功能过剩（版本化、i18n、博客），构建慢，配置项多。
不选纯静态 HTML：目录、搜索、导航全要手写，内容一多维护成本失控。
不选 Astro：侧边栏与搜索需自建，相对 VitePress 没有净收益。

    ├── cases/                      # 案例拆解

设计文档放仓库根的 `specs/` 而非 `docs/` 下，因为 `docs/` 是 VitePress 源目录，放进去会被构建成站点页面并污染搜索索引。

## 内容规划

### 板块一：创意方法论 `method/`

实写：

1. **从 brief 到成片：AI 创意广告完整链路 SOP** —— 六个阶段（拆 brief → 找洞察 → 定 Big Idea → 分镜 → 生成 → 合成），每阶段的输入、输出、AI 介入点与人工把关点。
2. **Big Idea 与洞察：AI 的能力边界** —— AI 擅长发散与执行，不擅长判断哪条洞察真的扎心。给出人机分工的判断标准。
3. **分镜设计：把创意翻译成模型听得懂的镜头语言** —— 景别、机位、运镜、光位的标准词表，以及一条创意如何拆成可生成的镜头序列。

占位（含写作模板）：品牌一致性控制、A/B 创意批量测试。

### 板块二：Prompt 模板库 `prompts/`

实写：

1. **Prompt 结构通法** —— 主体 · 风格 · 镜头 · 光影 · 参数 五段式，及其在图像与视频模型上的差异。
2. **产品静物 / 电商主图**
3. **短视频分镜脚本**
4. **广告文案与口播**

占位：人物代言、UGC 仿真风。

统一卡片格式，每个 Prompt 四段：**适用场景 / 可复制 Prompt / 参数说明 / 常见翻车点**。

### 板块三：工具地图 `tools/`

实写：

1. **全景对照表** —— 按文案、图像、视频、配音、剪辑五类列出主流工具与各自定位。
2. **选型决策树** —— 按「预算 × 交付形态」给出选型路径。

占位：单工具深度评测。

**准确性约束**：价格、参数上限、功能开关这类高频变动的信息一律标注「以官网为准」，不写具体数字。工具定位与适用场景属于相对稳定的判断，可以写。

### 板块四：案例拆解 `cases/`

实写：

1. **统一拆解模板** —— 创意点 → 生成链路 → 关键 Prompt → 可复用套路。
2. 两篇示例拆解，演示模板怎么用。

占位：使用者自己的实战案例。

## 关键配置决策

1. **`base` 设为 `/ai-creative-advertising/`**。用户尚未创建仓库。README 明确标注：若仓库名不同，只需改 `docs/.vitepress/config.mts` 中的 `base` 一行。此项配错的表现是线上页面样式与脚本全部 404。
2. **不执行 git push**。远程仓库不存在，README 提供完整的建仓、推送、开启 Pages 步骤。
3. **`lastUpdated` 依赖 git 提交时间**，首次构建（无提交历史）不显示，属预期行为。

## 验收标准

- `npm run docs:build` 零错误、零死链。
- `npm run docs:preview` 本地可访问，四个板块导航与侧边栏均可达。
- 搜索框可用，能检索到正文内容。
- README 中的部署步骤完整可照做。
